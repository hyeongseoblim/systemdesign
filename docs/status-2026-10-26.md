## V24 배포 준비

- 기존 migration 파일을 수정하지 않고 `V24__interactions_constraints.sql`을 추가했다.
- 질문 답변 `(card_id, question_id)`와 북마크 `(card_id WHERE question_id IS NULL)`의 중복을 막는다.
- 로컬 PostgreSQL 16 Testcontainers에서 `./gradlew test --tests com.jobstudy.curriculum.CurriculumMigrationTest --no-daemon` 실행 성공. 신규 DB 전체 적용과 V23→V24 업그레이드 테스트 2개가 실제 실행됐으며 skipped=0, failures=0, errors=0이다. 업그레이드 테스트는 추가 migration 1개 실행·Flyway validate·커리큘럼 384개 보존을 확인한다. 이는 운영 DB의 기존 interaction 데이터에 중복이 없다는 증명은 아니다.
- 배포 전 읽기 전용 운영 DB 조회 결과: 답변 중복 그룹 0, 북마크 중복 그룹 0, interactions 전체 0행, 게시 카드 129개. 아래 두 조회의 중복 그룹이 모두 0이므로 V24 인덱스 적용을 가로막는 기존 중복은 없다.

```sql
SELECT card_id, question_id, count(*)
FROM interactions
WHERE question_id IS NOT NULL
GROUP BY card_id, question_id
HAVING count(*) > 1;

SELECT card_id, count(*)
FROM interactions
WHERE question_id IS NULL
GROUP BY card_id
HAVING count(*) > 1;
```

- 운영 배포 후 Flyway V24 성공·health·카드 조회·관리자 인증 경계를 확인했다. 상세 결과는 배포 기록에 남겼다.
- 일반 웹은 브라우저 내 학습 저장을 유지하며, 관리자 전용 공유 답변 API를 사용자 동기화 기능으로 취급하지 않는다.
- 후속 요청으로 커밋·푸시·운영 배포가 승인됐다. 사전 검사 결과를 `5f7e5b7`로 커밋·푸시한 뒤 GitHub Actions로 API를 배포하고 Vercel의 동일 SHA 배포를 확인했다.
- 롤백 기준: 새 리비전 health 또는 게시 카드 조회 실패 시 이전 `jobstudy-api-00023-xqb`로 트래픽을 되돌린다. V24의 추가 인덱스는 이전 API와 호환되며, 이미지 롤백으로 DB migration 이력을 되돌리지는 않는다.
