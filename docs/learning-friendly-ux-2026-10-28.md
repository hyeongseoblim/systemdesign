# 학습 친화 UI/UX — 2026-10-28

## 개선 기준과 변경

지하철의 짧은 학습 시간에 한 장을 시작하고, 읽다가 멈추고, 내 말로 답한 뒤 다시 복습하는 흐름을 기준으로 했다.

| 관찰한 문제 | 변경 |
|---|---|
| 390px 홈에서 시작 영역이 상단 1,053px 아래에 위치 | 추천·이어서 학습할 한 장을 카테고리 앞에 배치. 시작 버튼이 320/390/768/1280px 첫 화면 안에 표시 |
| 질문 3개가 동시에 길게 나오고 마크다운 문법이 그대로 보임 | 한 질문씩 선택·이동, 작성 상태 표시, 마크다운 질문 렌더링, 이동 시 질문으로 시선·키보드 초점 이동 |
| 시작 카드에서 떠올린 답을 기록할 수 없음 | 기존 `jobStudy::quick::<cardId>`를 재사용하는 짧은 답변 입력 복원 |
| 점검 체크가 재진입 시 사라짐 | 질문별 체크·마지막 선택 문항을 브라우저에 저장 |
| 긴 도표의 제목 위치만 기억 | 제목과 구간 내 offset·비율을 함께 저장. 홈에서 바로 이어 읽기, 접힌 심화 본문 열기, 예전 제목 키 호환 |
| 고정 하단 버튼이 읽는 단계와 무관 | 본문에서는 질문, 질문에서는 이해도, 마무리에서는 다음 학습으로 연결. 심화 질문도 별도 인식 |
| 완료 후 다음 행동이 불명확 | 완료 안내와 다음 학습·복습 목록 링크 제공. 완료와 이해도는 계속 독립적으로 기록 |
| 브라우저의 직접 API 연결 지연·출처 차이 | 공개 카드 조회를 동일 출처의 웹 읽기 경로로 전달. 조회 시간 제한·목록 재시도 제공 |

읽기 진행은 스크롤 애니메이션 프레임에서 표시하고, 위치 저장은 짧게 지연하거나 링크 이동·탭 숨김 시 수행한다. 위치·체크 저장은 전체 학습 상태 이벤트를 발생시키지 않는다. 답변은 입력할 때마다 바로 저장해 이동 직전 입력이 사라지지 않게 한다.

복습 표시 해제는 해당 표시를 지우며, 사용자가 혼자 설명할 수 있다고 자동 평가하지 않는다. 이해도·체크리스트는 자기 점검이며 AI 채점이나 정답 판정이 아니다.

## 기록과 경계

- 기존 read/done/mastery/ans/quick 키와 `jobStudy::position::<cardId>`를 유지한다. 카드·질문 ID나 DB 스키마는 바꾸지 않는다.
- 신규 위치: `jobStudy::position-offset::<cardId>`에 sectionId, offset, fraction, viewportWidth. 폭이 바뀌면 구간 비율을 적용하며, 예전 제목 키만 있어도 이동 가능하다.
- 신규 선택·체크: `jobStudy::question::<cardId>::<sectionId>`, `jobStudy::checks::<cardId>::<questionId>`. 체크는 포인트 문구로 연결해 과거 기준이 현재 항목으로 잘못 복원되지 않게 한다.
- 저장 실패 시 화면의 답변은 유지하고 실패를 알린다. 자동 저장 성공으로 표시하거나 저장된 작성 개수를 늘리지 않는다.
- `/api/study/cards`와 `/api/study/cards/[id]`는 GET 공개 카드 읽기만 제공한다. 검색 인자 whitelist·UUID 검사·고정된 upstream을 사용하며 관리자 토큰과 임의 URL을 전달하지 않는다. 쓰기·관리자·유료 생성 경로는 제공하지 않는다.
- 공개 카드 목록만 서버에서 60초 재검증 캐시로 재사용하며 본문·질문 조회와 사용자 기록은 이 캐시에 넣지 않는다. 홈 복귀마다 3번의 느린 요약 조회를 반복하는 운영 관찰 결과를 반영했다. 서버 upstream 제한 25초, 기존 카드 조회·브라우저 제한 30초. 시크릿·IAM·Cloud Run 자원·유료 기능 설정은 변경하지 않는다.

## 검증 방법

```bash
cd apps/web
npm run test:study
npm run test:diagrams
npm run build
```

재현 가능한 로컬 UI 검사는 운영 네트워크와 분리한다. 로컬 fixture API는 저장소의 129개 실제 본문·질문 기준을 읽고 결정적인 테스트 ID를 사용한다. 운영 DB에 연결하거나 데이터를 쓰지 않는다.

```bash
# 터미널 1
npm run test:study:fixture
# 터미널 2: .env 파일은 바꾸지 않고 이 빌드에만 적용
NEXT_PUBLIC_API_BASE=http://localhost:8099 npm run build
npm run start -- --port 3000
# 터미널 3
npm run test:study:browser
```

로컬 검사 종료 후 fixture 서버를 종료하고 `npm run build`로 실제 환경의 빌드를 복원한다. 운영 브라우저 검사는 다음과 같이 실행한다. 각 검사는 격리된 브라우저의 localStorage만 사용한다.

```bash
WEB_BASE=https://jobstudy-eta.vercel.app UX_ARTIFACTS=/tmp/jobstudy-study-ux-production npm run test:study:browser
```

브라우저 검사는 첫 화면 진입점 4개 폭, 목록 실패·재시도, 시작 답변 저장·완료·다음 카드, 기존 답변·점검 체크·선택 문항 복원·복습 목록 복귀, 도표 중간 위치 직접 복원, 접힌 심화 본문 복원, 예전 제목 키, 공개 읽기 프록시 경계, 저장 실패, 작은 화면 다크 테마를 확인한다. 결과 JSON·스크린샷은 기본 `/tmp/jobstudy-study-ux`에 저장한다. 실기기·실제 지하철 네트워크 증거와는 구분한다.

## 로컬 검증 결과

- 콘텐츠 fixture로 브라우저 13개 시나리오 통과. 320/390/768/1280px의 시작 버튼 하단은 각각 약 547/520/421/430px로 첫 화면 안에 있었다.
- 도표 중간 2,783.44px에서 중단한 뒤 홈에서 복원한 위치는 2,783px였다. 접힌 심화 본문과 이전 제목 키도 복원했다.
- 기존 답변·새 답변·점검 체크·선택 문항·완료·복습 재진입, 복습 해제 시 이해도 자동 평가 방지, 저장 실패 안내를 확인했다.
- 학습 테스트 27개, 다이어그램 검사 2개 통과. fixture 설정 없이 실제 환경으로 다시 실행한 프로덕션 빌드도 성공했다.
- 직접 운영 API 연결 지연으로 로컬 UI 검사는 fixture와 구분해 수행했다. 운영 검증은 배포된 웹 주소의 동일 출처 읽기 경로를 통해 별도로 수행한다.
